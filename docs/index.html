GM Julian Vance

Sicilian Dragon Chess Coach

Two jobs, split cleanly. The board is legal chess plus a search stack (Lichess masters, Stockfish 18 WASM, then a local fallback). The words are Ollama Gemma 4, prompted with the live FEN. Express never plays chess itself — it proxies chat and queues engine jobs.

Express :3030 Ollama gemma4 Stockfish 18 NNUE Lichess Masters chess.js

2. Client state

currentRepertoire is black_dragon or white_attack. currentMode is tabiya or puzzle. moveHistory[] is the game tree. conversationHistory[] is what Gemma sees. 

stateDiagram-v2
  [*] --> Boot: DOMContentLoaded
  Boot --> TheoryBlack: setRepertoire black_dragon

  TheoryBlack --> TheoryWhite: Black / White toggle
  TheoryWhite --> TheoryBlack
  TheoryBlack --> PuzzleBlack: Puzzles mode
  TheoryWhite --> PuzzleWhite: Puzzles mode
  PuzzleBlack --> TheoryBlack: Theory mode
  PuzzleWhite --> TheoryWhite: Theory mode

  state TheoryBlack {
    [*] --> LoadTabiya
    LoadTabiya --> StudentToMove
    StudentToMove --> AutoOpp: legal student move + AUTO on
    AutoOpp --> StudentToMove: engine or book reply
    StudentToMove --> CoachStream: AUTO off
    AutoOpp --> CoachStream: after reply
  }

  state PuzzleBlack {
    [*] --> LoadPuzzleFen
    LoadPuzzleFen --> TryMove
    TryMove --> UndoWrong: SAN not in solutionMoves
    UndoWrong --> TryMove
    TryMove --> OppScript: correct + scripted opp
    OppScript --> TryMove
    TryMove --> Solved: last step correct
  }

3. A move on the board

Click, drag, a candidate chip, or a clickable SAN pill all land in handleMoveAttempt(from, to). chess.js is the only legal-move authority. 

flowchart TD
  Input["Click square, drop piece, candidate chip, or chat SAN"] --> Attempt["handleMoveAttempt from, to"]
  Attempt --> Legal{"chess.move OK?"}
  Legal -->|no| Reselect["Select that piece if it is side to move, else clear"]
  Legal -->|yes| Commit["Push moveHistory, play SFX, renderBoard"]
  Commit --> UIRefresh["renderMovesList, renderArrows, updateEvalBar, classifyMove"]
  UIRefresh --> GameOver{"chess.game_over?"}
  GameOver -->|yes| Modal["Game-over modal + coach recap"]
  GameOver -->|no| Mode{"currentMode"}
  Mode -->|puzzle| Puzzle["handlePuzzleMove"]
  Mode -->|tabiya| AutoQ{"AUTO on and opponent to move?"}
  AutoQ -->|yes| Opp["triggerAutoOpponentResponse"]
  AutoQ -->|no| Coach["Push analysis prompt, streamResponseFromOllama"]

4. Auto-opponent

After a 450ms pause the client asks the server engine. If that fails, it falls back to the hardcoded opening book, then the local heuristic search. 

flowchart TD
  Trigger["triggerAutoOpponentResponse"] --> Gate{"AUTO on, not player turn, not game over?"}
  Gate -->|no| Stop["Return"]
  Gate -->|yes| Wait["450ms think delay"]
  Wait --> API["POST /api/engine/bestmove FEN depth 14"]
  API --> Masters{"Early game and Lichess masters hit?"}
  Masters -->|yes| Play["Play top master SAN"]
  Masters -->|no or error| SF["queryStockfish queued WASM"]
  SF --> Have{"bestmove UCI?"}
  Have -->|yes| Play
  Have -->|no| Local["pickAutoOpponentMove"]
  Local --> BookHist{"OPENING_BOOK exact SAN history?"}
  BookHist -->|hit| Play
  BookHist -->|miss| BookTac{"OPENING_BOOK last SAN?"}
  BookTac -->|hit| Play
  BookTac -->|miss| Heuristic["calculatePositionSuggestions"]
  Heuristic --> Play
  Play --> Refresh["Render + classify + eval"]
  Refresh --> Over{"Game over?"}
  Over -->|yes| Modal["checkGameOverStatus"]
  Over -->|no| Narrate["Hidden prompt: student played X, opponent answered Y"]
  Narrate --> Stream["streamResponseFromOllama"]

5. Eval bar and arrows

The eval bar paints the local score immediately, then overwrites it with Stockfish after 150ms (use_book: false). Arrows still mix coach advice, puzzle targets, and the local suggestion cache.

  Fen --> Debounce["150ms debounce"]
  Debounce --> SF["POST /api/engine/bestmove depth 10"]
  SF --> Paint2["Overwrite bar with eval_score"]

  Fen --> Arrows["renderArrows"]

6. Coach stream

Every coaching turn rebuilds a system prompt from the live board. Replies are constrained to 2–4 sentences, no emojis, exact notation. 

sequenceDiagram
  autonumber
  actor Student
  participant App as app.js
  participant API as POST /api/chat
  participant Prompt as buildSystemPrompt
  participant Ollama as Ollama /api/chat

  Student->>App: Chat send, Ask Coach, Explain Move, or auto prompt
  App->>App: getCurrentBoardContext FEN, SAN, repertoire, mode
  App->>API: messages + board_context
  API->>Prompt: repertoire, mode, explaining_move
  Prompt-->>API: system GM Julian Vance
  API->>Ollama: system + conversationHistory stream true
  loop Tokens
    Ollama-->>API: NDJSON message.content
    API-->>App: SSE data content
    App-->>Student: Grow iMessage bubble, format SAN pills
  end
  Ollama-->>API: done
  API-->>App: data DONE
  App->>App: Push assistant turn onto conversationHistory

Dragon prompts stress ...Rxc3, the g7 bishop, c4, and ...d5. White 1.e4 prompts stress f7, Fried Liver, Evans, Morra, and Grand Prix. Native fetch is saved before Stockfish WASM loads so chat streaming still works.

7. Puzzle engine

Puzzles are scripted SAN lists, not Stockfish. A wrong try is undone. Hint draws a blue arrow and shows canned text — it does not call Ollama. 

flowchart TD
  Load["loadPuzzle: chess.load FEN, wipe history"] --> Play["Student move"]
  Play --> Match{"SAN in solutionMoves step.player?"}
  Match -->|no| Undo["SFX mistake, undo after 700ms"]
  Undo --> Play
  Match -->|yes| Next["SFX brilliant, step++"]
  Next --> Opp{"step.opp set?"}
  Opp -->|yes| Script["Play scripted reply after 500ms"]
  Script --> Play
  Opp -->|no last step| Win["handlePuzzleSolved: score, explanation, coach stream"]
  Hint["Hint button"] --> Arrow["Blue arrow on first accepted SAN"]
  Hint --> HintText["Show puzzle.hint, skip Ollama"]
  Reveal["Solution button"] --> Win
